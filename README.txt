Задание № 3 "Алгоритмические задачи".

Выполнил: Богдан Ноздряков.

В рамках задания реализованы два алгоритма сортировки:

1. Quick Sort (быстрая сортировка)
2. Selection Sort (сортировка выбором)

ВОЗМОЖНОСТИ
===========

Обе реализации:

- принимают массив элементов произвольного объектного типа
- позволяют сортировать элементы через Comparable
- позволяют задавать произвольный порядок сортировки через Comparator
- поддерживают сортировку по возрастанию и убыванию
- позволяют сортировать пользовательские объекты
- не изменяют исходный массив, а возвращают его отсортированную копию

Быстрая сортировка
==========

В текущей реализации данной сортировки:

1. Последний элемент диапазона выбирается в качестве опорного элемента (pivot)
2. Массив разделяется так, чтобы элементы, меньшие или равные pivot, находились слева от него, а остальные - справа
3. Получившиеся части массива рекурсивно сортируются тем же способом

Временная сложность:

- Лучший случай:  O(n log n)
- Средний случай: O(n log n)
- Худший случай:  O(n^2)

Худший случай возможен, например, для уже отсортированного массива, так как в данной реализации в качестве pivot всегда
выбирается последний элемент.

Дополнительная память:

Алгоритм быстрой сортировки использует рекурсивный стек:
- в лучшем O(log n)
- в среднем O(log n)
- в худшем случае O(n)

Кроме того, данная реализация создаёт копию входного массива размером O(n), чтобы не изменять исходные данные.

Поэтому общая дополнительная память текущей реализации во всех случаях составляет O(n).


Сортировка выбором
==============

Данная сортировка последовательно проходит по массиву.

На каждой итерации алгоритм:

1. Находит минимальный элемент в оставшейся неотсортированной части массива
2. Меняет его местами с элементом на текущей позиции
3. Повторяет операцию для следующей позиции

Временная сложность:

Лучший случай:  O(n^2)
Средний случай: O(n^2)
Худший случай:  O(n^2)

Классический алгоритм сортировки выбором использует O(1) дополнительной памяти во всех случаях.

Однако в данной реализации входной массив предварительно копируется, чтобы исходные данные не изменялись.
Поэтому общая дополнительная память текущей реализации составляет O(n) во всех случаях.


СРАВНЕНИЕ АЛГОРИТМОВ
====================

Временная сложность:

                     Быстрая сортировка   Сортировка выбором

Лучший случай            O(n log n)          O(n^2)
Средний случай           O(n log n)          O(n^2)
Худший случай            O(n^2)              O(n^2)

Быстрая сортировка в среднем значительно эффективнее на больших массивах, однако его производительность зависит от
выбора pivot.

Сортировка выбором проще по реализации, но имеет квадратичную временную сложность независимо от входных данных.


Дополнительная память классических алгоритмов:

                      Быстрая сортировка   Сортировка выбором

Лучший случай            O(log n)            O(1)
Средний случай           O(log n)            O(1)
Худший случай            O(n)                O(1)

По дополнительной памяти классический алгоритм сортировки выбором эффективнее алгоритма быстрой сортировки:
он использует O(1) памяти во всех случаях, тогда как быстрая сортировка требует память под
рекурсивный стек - O(log n) в лучшем и среднем случаях и O(n) в худшем.


В данной реализации оба алгоритма перед сортировкой создают копию входного
массива, чтобы не изменять исходные данные. Копия требует O(n) дополнительной
памяти.

Поэтому с учетом копирования массива дополнительная память текущих реализаций
составляет:

                      Быстрая сортировка   Сортировка выбором

Лучший случай            O(n)                O(n)
Средний случай           O(n)                O(n)
Худший случай            O(n)                O(n)


COMPARABLE И COMPARATOR
=====================

Для элементов, реализующих Comparable, доступна сортировка по естественному порядку:

    Integer[] numbers = { 5, 2, 8, 1 };
    Integer[] sorted = QuickSort.sort(numbers);

Для задания собственного порядка сортировки используется Comparator:

    Integer[] sorted = QuickSort.sort(
        numbers,
        Comparator.reverseOrder()
    );

Таким образом, те же алгоритмы можно использовать не только для чисел, но и для строк или пользовательских объектов.

Пример сортировки пользовательских объектов:

    Person[] sorted = QuickSort.sort(
        people,
        Comparator.comparingInt(Person::age)
    );

ОСОБЕННОСТИ РЕАЛИЗАЦИИ
======================

Методы сортировки не изменяют переданный массив. Перед сортировкой создаётся его копия.
Это позволяет использовать исходные данные после вызова метода без каких-либо изменений.

Для сравнения элементов используется Comparator, благодаря чему алгоритмы не зависят от конкретного типа данных.
Если Comparator явно не передан, используется естественный порядок элементов через Comparator.naturalOrder().
